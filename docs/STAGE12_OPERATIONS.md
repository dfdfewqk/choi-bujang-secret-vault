# 12단계 탈환 작전실 — 실제 결과와 재현 안내

## 출처와 검사 기준

- 제공 엔진: **ALEPH SDP 엔진**. 반 엔진이 확인한 신원·기기·경로를 학생 판정기에 전달하는 공식 계약은 `docs/DECIDER_REQUEST.md`입니다. 학생은 엔진을 개발하거나 포장했다고 주장하지 않습니다.
- 학생 작업: `src/decider.mjs` 판정 규칙, `src/detect.mjs` 탐지 규칙, 자료실의 JWT/소유권 검사, 학생 앱 공개키 승인·서명 검증, 백업 복구, 작전실과 가린 API 기록.
- 1~11단계 보존 기준: `d5d1284bf0fef1b8a9ee50bb95844719dd1b1e50`. 12단계 최종 검사/배포 커밋은 `/aleph.json`의 **전체 commit**과 제출 JSON의 commit을 비교합니다. README 안에 자기 커밋 SHA를 가짜로 고정하지 않습니다.
- `byteback.app.request.v1`은 학생 자료실의 추가 검증 계약이며 제공 엔진의 앱 서명 규격과 동일하다고 주장하지 않습니다. 공식 시험 41종의 이름이나 결과를 임의로 만들지 않습니다.

## 화면과 실제 API

자료실에서 로그인 → 기기 승인 요청 → 운영자 확인 → 승인 결과 확인 → **탈환 작전실 열기**. 키/토큰은 페이지 메모리에만 있으므로 작전실은 같은 페이지 대화상자로 엽니다. 새로고침/화면 이동 후 재로그인·재승인이 필요합니다.

`GET /api/operations`는 JWT와 승인 기기 서명을 모두 검증한 뒤 서버 DB 스냅숏을 읽습니다. 다른 owner를 본문/쿼리로 선택할 수 없고 POST도 받지 않습니다.

- 규칙: 실제 코드의 RULE_IDS와 파일 사본 해시 검증 결과. 엔진 판정 사건을 수신한 것과 구분합니다.
- 탐지: DB에 저장된 이 계정의 최근 10분 메모 GET 요청(최대 2,000개)을 학생 탐지기로 평가합니다. 신원은 서버 검증 JWT에 바인딩된 owner로 묶으며 응답에 owner는 내보내지 않습니다. 제공 엔진 사건 스트림은 미연결입니다.
- 회수: 기기의 pending/approved/revoked/expired 상태는 실제 DB 결과입니다. **신원 회수 집행은 미연결**이고 기기 승인 취소와 같다고 표시하지 않습니다. `propose_revocation`을 집행 완료로 바꾸지 않습니다.
- 복구: 현재 owner의 복구 감사 건수/최신 확인 시각/사본 해시와 정책 사본 버전입니다. 기록이 없으면 기록 없음으로 표시합니다.
- 실제 API 관측: 현재 계정 + 익명 서비스 요청의 최근 100개, 전체 관측 건수. 다른 계정의 인증된 기록은 제외합니다. 과거 배포 기록은 행별 commit으로 구분합니다.
- 공식 41종: 결과 미연결. 실행/통과 수는 **미확인(null)**이며 자체 점검과 합산하지 않습니다.

관측 JSON에는 요청 ID, 서버 시각, method, route 분류, 실제 상태 코드, 가린 error code, 배포 commit만 담습니다. 토큰·헤더 원문·메모 본문·제목·사용자 ID·IP·실제 자원 ID·기기 공개키를 저장하거나 표시하지 않습니다.

메모/기기/복구/작전실 API의 실제 응답에 `X-Request-Id`, `X-Checked-At`, `X-Audit-Recorded`, 가능하면 `X-Deployment-Commit`을 붙입니다. 감사 저장에 실패해도 기존 응답을 성공으로 바꾸지 않으며 `X-Audit-Recorded:false`로 알립니다. 기록 없음을 시험 성공이나 0건 탐지 증거로 해석하지 않습니다.

## 실제 점검 표와 미실행 절차

**안전한 조회 점검 실행**은 다음 6개 HTTP 요청을 실제 전송합니다. 메모 응답 본문은 읽거나 표에 표시하지 않습니다.

| 구분 | 실제 요청 | 기대 |
|---|---|---|
| 공개 자료 제거 | GET /data.json | 404 |
| 무인증 메모 | GET /api/notes, 토큰 없음 | 401 |
| 잘못된 로그인 | GET /api/notes, 잘못된 Bearer | 401 |
| 앱 서명 없음 | 유효 로그인만으로 GET /api/notes | 403 |
| 승인된 정상 요청 | 승인 기기로 서명 GET /api/notes | 200 |
| 정상 작전실 | 승인 기기로 서명 GET /api/operations | 200 |

각 행은 기대/실제 상태/요청 ID/서버 확인 시각/감사 저장 여부/배포 commit을 표시합니다. 정적 경로에 요청 ID가 없으면 `x-vercel-id`를 별도 출처로 표시하고 서버 메타데이터 자체가 없으면 미제공으로 둡니다. 연쇄 요청이 실패하면 실패·미확인으로 기록하며 PASS를 만들지 않습니다.

그 밖의 1~11단계 대표 사례도 같은 표에 미실행으로 남깁니다. 후속 운영 검증 순서는 다음과 같습니다.

1. 격리된 공식 시험 A/B 신원으로 A 메모 생성, 본인 GET 200과 B GET 404를 비교합니다. 실제 학생 자료는 사용하지 않습니다.
2. 원본 DB의 유효 anon/authenticated 시험 역할 조회 거부를 확인합니다. API 키 누락 401을 RLS/권한 검증으로 대신하지 않습니다.
3. ALEPH SDP 엔진에서 미등록 기기, 복합 이상 접속, 추가 인증 정상 요청, 구역 밖 조회를 전송하고 실제 판정 기록을 받습니다.
4. 신원 회수 집행 경로가 연결된 경우에만 실제 조회 폭주→회수 제안→집행→재요청 거부를 확인합니다. 지금은 집행 미연결입니다.
5. 시험 B의 신규 사본에 대해 복구 preview→변조/삭제 복원→정상/금지 요청 재전송을 확인합니다. 정상 학생의 기존 메모를 변조하지 않습니다.
6. 서명 후 다른 경로·본문으로 바꾼 요청의 거부와 정상 서명 요청 허용을 함께 기록합니다.
7. 공식 심판 41종은 심판 결과가 확인된 경우에만 결과로 분류합니다. local synthetic, Node 회귀, SQL 롤백, 운영 HTTPS, 공식 심판을 구분합니다.

## 제출 번들의 제한된 공개 읽기 점검

`npm run bundle`은 별도 12단계 검사기에서 공개 HTTPS GET 경로 8개만 검사합니다. 여기에는 공개 매니페스트, 공개 파일, 무인증 메모·단건·복원·기기·작전실 조회와 공개 홈페이지가 포함됩니다. 비공개 메모/API 응답 본문은 읽지 않으며 `/aleph.json` 공개 본문만 최대 4096자로 제한해 단계 정보를 확인합니다. GET 결과에 기록된 HTTP 상태는 실제 자체 관측이며, 공식 심판의 방어 통과 영수증이 아닙니다. 타임아웃·통신 실패 시 `not_run`을 기록하고, 인증·쓰기·사용자 A/B·엔진 회수·공식 41종 시험은 실행하지 않습니다. 기존 작전실의 로그인 뒤 6개 운영 점검은 별도 기능으로 유지됩니다.

## 설치·실행·중지

### 학생 판정기·탐지 규칙

```bash
git clone https://github.com/dfdfewqk/choi-bujang-secret-vault.git
cd choi-bujang-secret-vault
git checkout <검사한 실제 40자리 커밋>
npm ci
npm run decider:test
npm run detect:test
node --test test/*.test.mjs
```

Node.js 22 이상을 사용합니다. 명령 종료로 로컬 검사가 중지됩니다. 판정기/탐지기는 실제 엔진·회수 서비스의 시작 명령이 아니며 로컬 검사 통과를 엔진 방어 성공으로 표시하지 않습니다.

### 접속 앱·자료실·작전실

- 운영 실행: 기존 Vercel 배포 URL을 엽니다. 설치형 화면은 브라우저의 앱 설치 기능을 사용하며 별도 접속 프로그램은 없습니다.
- 정적 빌드: `npm run build -- --local`. 이 명령은 실제 API 서버를 실행하지 않습니다.
- 로컬 API 재현이 필요하면 기존 Vercel 프로젝트 연결을 사용하고 서버 환경변수는 공식 관리 화면에서 구성합니다. 환경변수 값이나 토큰을 README/로그/ZIP에 넣지 않습니다.
- 중지: 앱에서 로그아웃하고 탭을 닫습니다. 메모/감사 자료를 삭제하지 않습니다. 승인 취소가 필요하면 `docs/STAGE11_APP_APPROVAL.md`의 특정 기기 취소 절차를 따릅니다.
- 운영 호스팅 중지가 필요하면 해당 프로젝트의 관리 기능으로 중지합니다. 다른 프로젝트나 DB는 변경하지 않습니다.

## 복구

1. `git status`와 `git diff`로 이번 변경과 다른 작업을 나눠 대상/영향을 확인합니다. `git reset --hard`는 쓰지 않습니다.
2. 코드 복구는 검증된 이전 커밋의 필요한 파일만 별도 브랜치에 복원하고 회귀 검사 후 하나의 검토 배포로 진행합니다.
3. 12단계 기록 테이블은 새 관측 자료입니다. 코드 복구 때 메모·백업·기존 감사·관측 자료를 DROP/DELETE하지 않습니다.
4. 메모 복구는 `docs/STAGE10_BACKUP_AND_RESTORE.md`의 시험 B 한 건 복구 절차를 따릅니다. 사본 없거나 hash/owner/ID 불일치면 중단합니다.
5. 복구 후 무인증/타인/미등록/서명 없음/구역 밖 거부와 정상 승인 요청 허용을 다시 확인합니다. 하지 않은 것은 미실행입니다.
6. 배포 manifest commit과 검사 commit을 맞춘 뒤 `npm run bundle`. 제출 JSON은 생성물이며 Git에 커밋하지 않습니다.

## 이번 검증

- Node 회귀 139개 통과, 실제 응답과 감사 ID/시각 상관관계, 감사 장애 표시, 계정 접근 차단, 미연결/미실행 표시 및 20개 제출 점검 한도 검사.
- 실제 DB에 가상 계정 A/B + 익명 관측을 저장해 owner 분리·상태 일치·조회 사건 분리·권한 차단을 검사 후 ROLLBACK. 기존 메모 5건 유지, 시험 관측 잔여 0건.
- 기존 1~11단계와 XDR는 회귀 검사로 확인합니다. 공식 12단계/41종, 실제 신원 회수 집행 및 운영 시험 JWT 전체 흐름은 미실행입니다.
